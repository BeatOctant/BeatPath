# ミックスの処理と画面遷移（改善案と、今のコードとの比べ）

2026-10-08。OctantPath の中の作りの記録で、仕様ではない（仕様は OctantSpecs）。

## 1. あるべき形（今のコードを見ずに立てた案）

目指す体験は「1 曲を選ぶと、そこから並びができて、上から順に遊んでいける」こと（YouTube Music のミックスリスト）。OctantPath は並びを出し、遊ぶ準備をし、遊び終わったら次へ送る。曲を始めるのはゲームの PLAY。

### 状態

| 状態 | 板の見え方 | 次へ進むきっかけ |
| --- | --- | --- |
| なし | 「〇〇からミックス」（〇〇は曲選択で選んでいる曲。選んでいなければ押せない） | ミックスを押す |
| 並びを作っている | 「並びを作っています」。ほかのボタンは押せない | 推薦が届く |
| 並びがある | 並び。今の曲に ▶。各曲に「入っている / 取得中 / 未取得 / 取れない」 | 並びの曲を選ぶ、チップ、遊び終わる |
| 曲から外れた | 並びはそのまま。「ミックスの外の曲を選んでいます」 | 並びの曲を選ぶと戻る |

### 決まりごと

1. **曲選択の選択を変えてよいのは、ユーザーが頼んだときだけ。** 並びの曲を選んだとき、「取得」を押したとき、ミックスの曲を遊び終えて戻ったとき。それ以外（前もっての取得が終わったときなど）には変えない
2. **ユーザーが曲選択でミックスの外の曲を選んだら、ミックスは止まる。** 遊び終えても次へは送らない。並びの曲を選べば戻る
3. **前もっての取得で画面を揺らさない。** 取得は裏で進めるが、SongCore の読み直し（曲の一覧が作り直され、選択が外れる）は、画面が切り替わるときにまとめて行う。具体的には、遊び終えてメニューに戻ったとき、またはユーザーがその曲を今すぐ使いたいとき（「取得」、並びで選んだ曲が置いただけで読み込み前）
4. **置いただけのマップは、読み込みを確かめるまで取得済みにしない**（OctantPath 法 2.5）。置いたことは記録しておき、ゲームを閉じても次の起動の読み込みで確かめて所有を記録する（3.1 の証拠を失わない）
5. **取得が重なっても失敗にしない。** 前もっての取得の最中に「取得」を押したら、その曲を先にして待つ。すでに取得中の曲なら、それが終わるのを待つ
6. **チップで並びを作り直しても、今の曲を見失わない。** 新しい並びに今の曲があれば、そこに ▶ を付けたままにする
7. **1 行の案内で、次に何をすればよいかを出す。**「PLAY で始められます」「取得中…」「取れない曲です」など

### 画面遷移

```
並びの曲を選ぶ
 ├ 入っている   → 曲選択で選ぶ（ゲームの試聴が流れる）→ PLAY
 ├ 未取得       → BeatSaver の試聴 →「取得」→ 取得 → 読み直し → 曲選択で選ぶ → PLAY
 ├ 取得中       → 終わるのを待って曲選択で選ぶ
 └ 取れない     → 案内だけ
遊び終えて戻る（ミックスの今の曲だったとき）
 → 結果画面（次の曲を覚えるだけ。結果画面で選んだ未取得の曲は置くところまで取る。選んだ曲が置けたら Continue を押す）
 → Continue で曲選択に戻る → まとめて読み直す → 次の曲へ ▶ を進める → 入っていれば曲選択で選ぶ → その先を前もって取る
```

## 2. 今のコードとの比べ

| 決まりごと | 今のコード | 差 |
| --- | --- | --- |
| 1 選択を変えるのは頼まれたときだけ | 並びで選ぶ、「取得」、遊び終えたときに選ぶ。読み直しで外れたときにも選び直す（外れたときだけ） | 選び直し自体が、読み直しのたびに起きる。3 で読み直しを減らせば要らなくなる |
| 2 外の曲を選んだら止まる | 遊び終えた曲がミックスの今の曲のときだけ次へ送る | ほぼ合っている。止まっていることが板に出ていない |
| 3 取得で画面を揺らさない | 前もっての取得のたびに、すぐ SongCore を読み直す | **ここが「遷移が素直でない」の主な原因**。読み直しで一覧が作り直され、選択が外れてちらつく |
| 4 置いただけのものは取得済みにしない | 読み直しのあとに確かめ、所有を記録する | 読み直しを後回しにするなら、置いたことの記録が要る |
| 5 取得が重なっても失敗にしない | 取得中は次の取得を断り、「ほかの曲を取得中です」と出す | 差あり |
| 6 チップで今の曲を見失わない | 並びを作り直すと今の曲が消える | 差あり |
| 7 1 行の案内 | ある | 各曲の「取得中」が出ない |
| 「〇〇からミックス」 | ボタンは「ミックス」で、起点は見出しの行に出る | 小さな差 |

## 3. 直すこと

- 取得と読み直しを分ける。前もっての取得は置くところまでで止め、置いたことを `UserData/OctantPath/placed.json` に記録する。読み直しは、遊び終えてメニューに戻ったときと、ユーザーがその曲を今すぐ使うときにだけ行い、読み直しのあとで置いたものをまとめて確かめて所有を記録する。起動時の読み込みのあとにも確かめる
- 取得を順番待ちにする。「取得」は前もっての取得より先に回し、断らない
- チップで作り直しても、今の曲に ▶ を残す
- 各曲に「取得中」を出す。ミックスの外の曲を選んでいるときは、そう出す

## 4. 2026-10-10 の作り（手札と下見）

上の 1〜3 のあと、デスクトップモードで触りながら直した形。

### 流れ

1. 曲選択の上の板には、推薦のカード（「ミックス」と、起点の要らない手札）と「保存」「移動」だけを出す。並びの一覧は既定で出さない（`mixListOnPanel`）
2. 「ミックス」（板か、曲の詳細のアルバムアートの左上の ♪）を押すと、中央の画面に種類の小窓が出る。種類は OctantCompass の `/v1/presets` の一覧からタイルで作り、`group` があれば見出しで分ける
3. 種類を選ぶと下見の小窓に変わる。`mixDraftCount`（10）曲を並べ、残り 2 倍を入れ替え用に持つ。1 曲目の試聴を自動で流す。試聴の音源を取っている間は前の曲を流したままにし、選んだ行の薄い塗りを左から伸ばして左端の帯を淡くする。伸び方はおもに時間で決める（受け取った割合は途中をほとんど返さない）。これまでに取るのにかかった時間の目安で 8 割ほどに届く見込みと、受け取った割合の大きい方へなめらかに寄せ、取り終えたら残りを 0.35 秒ほどで埋める（取れなければ前の曲を止める）。「作成」はゲームの PLAY と同じ主ボタン。各行の ✕ で外す（入れ替えない。曲数が減る）、⇔ で入れ替え、↓ でその曲だけ取得（台帳の枠は「手動」）。取得が済んだ曲（入っている曲も）は ↓ の場所が ▶ になり、押すと読み直して曲選択でその曲を選び、下見の小窓は閉じる（下見は残す。PLAY はユーザー）。その曲を遊んで曲選択に戻ると下見の小窓を開き直す（結果画面でおすすめを選んだときは開かない。2026-10-22）。一覧の一番下の「曲を足す」の行で、入れ替え用の次の曲を一番下に足す（20 曲まで。`MixDraftRules.MaxSize`）。入れ替え用が 3 曲を下回ったら、同じ条件でこれまで出した曲を除いて追加を受け取る。1 曲目の試聴を取り終えたら、並んだ曲の試聴を上から 1 曲ずつ先読みする（同時には取らない。小窓を閉じたらやめる。取るのはカバーと同じく並んだ曲の分だけ。持っておく音源は 40 まで。2026-10-22）。推薦された hash の版が BeatSaver にない曲は出さない（Core の RecommendationDisplay.Shows。2026-10-11）
4. 「作成」で並んでいる曲だけを取得し、進み具合を小窓の帯に出す（結果画面の帯と同じ `SmoothProgress` で、おもに時間で伸ばし、受け取った割合と取り終えた曲数の大きい方へ寄せる。取り終えたら満ちたまま、曲の読み直しが終わるまで残す）。終わったら一時的なプレイリスト `OctantPath-mix-current`（OctantPath の印付き。自動削除から守らない）を書き、曲選択でそのプレイリストを開く。小窓は開き直す直前にアニメーションなしで閉じる
5. 遊び終えると、結果画面の上の小さな板に、遊んだ譜面を起点にしたおすすめを 3 曲出す。板は曲選択の板と下の縁をそろえて置き、曲選択の板の固定を外している間は上の縁の真ん中につまみを出す（どちらの板のつまみで動かしても、2 枚とも動く）。行は下見の小窓と同じ（✕・⇔・↓ は出さず、各行に ▶ を出す）。行を押すとその曲の試聴だけを流し（取っている間の見た目は下見の試聴の行と同じ）、結果画面を離れたら止める。試聴中の行と ▶ で選んだ行は、試聴中の行と同じ帯と塗りで出す。▶ を押すとその曲を次の曲にし（押しただけで曲選択へ移ると、聞いてから決められなかった。2026-10-24）、曲選択に戻ったときにミックスのプレイリストにも入れる。入っていればそのまま Continue を押し、入っていなければ取って（進み具合は板の帯に出す。伸び方は下見の試聴の行と同じ `SmoothProgress` で、おもに時間で決める）置けたら Continue を押す。取っている間は選び直せず、先に Continue を押しても取り終わるまで次へ進まない。取れなければ板に理由を出し、Continue は押さない。取っている間に遊び直したら（Restart）、その曲は捨て、新しい結果画面の Continue は押さない
6. OctantCompass につながらないとき、推薦の要求が失敗したときは、中央に 3 秒の知らせを出す
7. 次の曲へ進むのは、板の「自動で次へ」が入のとき（`mixAutoAdvance`。結果画面で選んだ曲は切っていても選ぶ）。進む（読み直し、曲選択での選択）のは、結果画面を閉じて曲選択が 0.5 秒続けて出てから。今の一覧で選べないときは、ミックスのプレイリストで曲選択を開き直す（ミックスがなければ「すべて」）
8. ミックスで取ったマップ（台帳の枠は「ミックス」）は、お試し中・残すのあいだ `OctantPath-mix`（OctantPath ミックス）に出す。ほかの枠のプレイリストと同じく台帳から作る表示で、自動削除からは守らない
